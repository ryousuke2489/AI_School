## 1. プロンプトエンジニアリングとは何か

### なぜ「聞き方」で結果が変わるのか

- **プロンプト**: AIに与える指示文・入力テキストのこと
- **プロンプトエンジニアリング**: 望む結果を得るためにプロンプトを設計・最適化する技術
- LLMは「確率的に次の単語を予測する」仕組み
  - → 入力（プロンプト）が変われば、出力も大きく変わる
- プログラミング不要で、**誰でも実践できる**スキル

---

## 同じ質問でも結果が変わる例

### 悪い例
```
AIについて教えて
```
→ 漠然とした長い回答が返ってくる

### 良い例
```
ビジネスパーソン向けに、生成AIの主要な3つの
活用領域を、それぞれ50文字以内で簡潔に説明
してください。
```
→ 構造化された的確な回答が得られる

## 2. 効果的なプロンプトの基本構成

### 5つの構成要素

| 要素 | 説明 | 例 |
|------|------|-----|
| **役割設定** | AIに演じてもらう役割 | 「あなたはマーケティングの専門家です」 |
| **指示** | 実行してほしいタスク | 「以下の文章を要約してください」 |
| **文脈** | 背景情報・状況説明 | 「新製品のプレスリリース用に」 |
| **制約条件** | 出力の制限や条件 | 「200文字以内で」「箇条書きで」 |
| **出力形式** | 回答の形式指定 | 「表形式で」「JSON形式で」 |

---

## プロンプト構成の実例

```markdown
# 役割設定
あなたは経験豊富なビジネスライターです。

# 文脈
当社は中小企業向けのクラウド会計ソフトを
提供しています。新機能のリリースを告知します。

# 指示
以下の新機能について、プレスリリースの
リード文を作成してください。

# 制約条件
- 200文字以内
- 専門用語は避け、平易な言葉で
- 導入メリットを明確に

# 入力データ
新機能: AIによる自動仕訳機能
```

[図: プロンプトの5つの構成要素を色分けして示す図]

## ロールプロンプティング

### 役割を設定することで回答の質が変わる

- **役割なし**: 一般的な回答になりがち
- **役割あり**: 専門性や視点が反映された回答に

### 効果的な役割設定の例

- 「あなたはデータサイエンティストです」
- 「あなたは小学校の先生です。小学5年生にもわかるように説明してください」
- 「あなたはセキュリティコンサルタントです。リスクの観点から評価してください」

役割設定によって、回答の**専門性・詳しさ・視点**が変化する

## 3. 基本テクニック

### Zero-shot プロンプティング

- **例やお手本を示さず**に、指示だけでタスクを実行させる
- 最もシンプルなプロンプト手法

```
以下の文章のトーンをポジティブにしてください。

文章: 「今日の会議は長くて退屈だった。」
```

- LLMの汎用的な言語能力に頼る手法
- 単純なタスクには十分効果的

---

## Few-shot プロンプティング

### 例を示すことで出力の精度を上げる

- **One-shot**: 1つの例を提示
- **Few-shot**: 2〜5個の例を提示

```
以下の形式で、商品レビューの感情を分類して
ください。

レビュー: 「この商品は最高です！」
感情: ポジティブ

レビュー: 「期待外れでがっかり」
感情: ネガティブ

レビュー: 「値段の割には悪くない」
感情:
```

## 4. 応用テクニック

### Chain of Thought（CoT: 思考の連鎖）

- AIに**段階的に考えさせる**ことで、推論の精度を向上
- 「ステップバイステップで考えてください」と指示

```
問題: 花屋で5本のバラを買いました。1本300円
です。1000円札で支払った場合、おつりはいくら
ですか。ステップバイステップで考えてください。

回答:
1. バラ5本の合計金額: 300円 × 5 = 1,500円
2. 1,000円では足りないため、支払えません。
```

- 特に**数学的問題**や**論理的推論**で効果が高い

---

## Step-by-step と 自己整合性

### Step-by-step（段階的指示）
- タスクを複数のステップに分解して指示
- 複雑なタスクを確実に実行させる

```
以下の手順で市場分析レポートを作成して:
1. まず市場の現状を3行で要約
2. 次に主要プレイヤーを3社挙げる
3. 最後に今後のトレンドを予測
```

### 自己整合性（Self-Consistency）
- 同じ問題に対して**複数回回答させ**、最も一致する答えを採用
- 回答の信頼性を高めるテクニック

---

## ReAct パターン

### 推論（Reasoning）と行動（Action）を交互に行う

- AIが「考える」→「行動する」→「観察する」を繰り返す
- より複雑なタスクに対応可能

```
質問: 東京タワーとスカイツリーはどちらが高い？

思考: 両方の高さを比較する必要がある
行動: 東京タワーの高さを確認 → 333m
観察: 東京タワーは333m
思考: 次にスカイツリーの高さを確認
行動: スカイツリーの高さを確認 → 634m
観察: スカイツリーは634m
結論: スカイツリー（634m）が東京タワー（333m）
     より301m高い
```

## 5. やってはいけないアンチパターン

### 避けるべきプロンプトの例

| アンチパターン | 悪い例 | 改善例 |
|----------------|--------|--------|
| **曖昧な指示** | 「いい感じにして」 | 「ビジネスメールの形式に書き換えて」 |
| **矛盾する条件** | 「短く、かつ詳細に」 | 「3行で要点を述べて」 |
| **過剰な指示** | 20個以上の条件を列挙 | 重要な条件5個に絞る |
| **否定形のみ** | 「〜しないで」だけ | 「〜してください」と肯定で指示 |
| **文脈なし** | 「これを直して」 | 背景と目的を明示して依頼 |

---

## Temperature（温度）パラメータ

### 出力のランダム性を制御する設定

- **Temperature低い（0〜0.3）**: 確定的・一貫性のある回答
  - 向いているタスク: 翻訳、データ抽出、分類
- **Temperature高い（0.7〜1.0）**: 創造的・多様な回答
  - 向いているタスク: ブレインストーミング、創作、アイデア出し

## 6. 実践演習：タスク別プロンプト設計

### 代表的なタスクとプロンプト例

**要約タスク**:
```
以下の文章を、中学生でもわかるように
3文以内で要約してください。

[対象文章]
```

**翻訳タスク**:
```

してください。ビジネス用語はそのままカタカナ
表記を残してください。

```

## キーワード・用語解説

| 用語 | 説明 |
|------|------|
| プロンプト | AIに与える指示文・入力テキスト |
| プロンプトエンジニアリング | 効果的なプロンプトを設計する技術 |
| Zero-shot | 例なしで指示するプロンプト手法 |
| Few-shot | 数個の例を示すプロンプト手法 |
| Chain of Thought | 段階的に推論させるテクニック |
| ロールプロンプティング | AIに役割を設定する手法 |
| Temperature | 出力のランダム性を制御するパラメータ |
| ReAct | 推論と行動を交互に行うパターン |
| システムプロンプト | AIの振る舞いを事前設定する指示文 |

---

## まとめ

- プロンプトエンジニアリングは**AIを効果的に使うための必須スキル**
- プロンプトは**役割設定・指示・文脈・制約条件・出力形式**の5要素で構成
- **Zero-shot**はシンプルだが、**Few-shot**で例を示すと精度向上
- **Chain of Thought**で段階的に考えさせると推論精度が上がる
- **曖昧な指示**や**矛盾する条件**はアンチパターン
- タスクの性質に応じて**適切なテクニックを選択**することが重要
